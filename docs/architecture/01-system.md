# 世界系统 v0.6

## 世界先成立，AI再表达

玩家留下梦种 → 保存素材事实 → 规则产生候选方案 → 玩家选择/角色计划 → 检查前提 → 发生事件并更新状态 → 写入经历与知识 → 影响下一次选择。自然语言只是这个过程的可读表达。

`life.js` 是独立于画面的纯 JavaScript 世界引擎。输入为状态和绝对时间；不会访问网络、DOM或浏览器存储。`app.js` 用状态渲染场景、处理邀请；`storage.js` 保存；`gomoku.js` 负责棋局；`games.js` 是数独、拼片、翻牌纯规则，`games-ui.js` 是其界面；`scenes.js` 提供场景和各自寻路区域。

## 小脑袋

候选活动有基础倾向，受天气、精力、性格偏好、当前知识和未完成梦种影响。先筛去不满足硬条件的动作，再用保存的随机种子进行带权选择。高分意味着更常发生，不等于每次必选。选择时保存理由和候选分数，不能事后让AI补编动机。

本版实现：读书、喝茶、研究、休息、看天气、制作、采集、厨房、整理、看鸟、观星、野餐、六项兴趣计划、陪玩家玩八种游戏。v0.5新增真实河畔钓鱼、农事与逛店；钓鱼仍检查鱼竿与鱼饵。v0.6原角色有四方向步行与六种活动姿态，活动含义以真实状态为准。

## 时间与连续生活

活动含 startedAt、endsAt、durationMs、progressBase。打开游戏不重抽活动、不重置进度。暂停存入栈，邀请结束后恢复剩余时长与章节。离开期间不需让电脑常开，下次按事件时间逐步结算。种植增长按时间区间计算，并保存生长基准，避免频繁打开比离线打开多长一截。

正常阅读时长数小时。首个梦种研究45秒、制作45秒，植物生长约90秒，雨天约65秒，是明确的Demo加速。没有把真实时间假装成已联网运行的服务器。

## 硬规则和软因果

硬规则：没有知识不能制作相应梦种；植物的雨水/浇水影响水分和成长；已产出的同一物件不能重复发放；没有鱼竿不能选钓鱼。

软因果：她可能因喜欢阅读和下雨选择读书；精力低时更偏向休息；新梦种提高研究倾向。未来AI可以提出符合现有动作与素材库的建议，规则校验后才可生效。

示例因果链：你记录植物梦种 → 她查书 → 得到这颗梦种的照料知识 → 种下植物 → 雨/照料使其成长 → 纸鹤带来旧温室便笺。便笺存在，完整温室地图与NPC尚未实现。

## 三层记忆

1. 素材记忆：`fragments` 保留梦种原文和时间，是故事的来源。
2. 经历记忆：`events` 保存决策、学习、制作、生长等因果事件；`memories` 是精简的可读重要经历，普通走动不入账。
3. 长期记忆：`knowledge` 保存已学会的知识与来源；`preferences` 保存性格倾向。当前尚未实现复杂性格随经历演化。

每层都有稳定ID。产物带 sourceIds，能找回原文和相关经历；新梦种可关联旧物的素材来源。事件历史有Demo容量上限，并非无限数据库或语义向量记忆系统。

## AI边界

现版本为本地组合规则，另有手动 ChatGPT 往返：用户查看并复制材料，自行提交给 ChatGPT，再导入结构化JSON。只接收 name、description、kind、color、thought 等展示提案；梦种来源、知识门槛、时间与奖励由引擎控制。禁止执行模型给的代码，禁止直接插入HTML。

将来自动接口接入应置于独立适配器，沿用同一个校验入口。ChatGPT订阅与API计费分开；当前没有后台AI自动调用或API密钥。

## v0.3扩展

具体前提、时长和产出见 design/04-courtyard-and-games.md。`home` 保存有限材料、舒适度、摆放、灯光和鸟饮水；开始厨房/野餐时只取一次资源，暂停恢复不重取。`playbox` 保存三种新小游戏。视角与角色所处场景分开；仅邀请生活行为才改变角色活动。

时间来自设备；UTC偏移入档并在打开时更新。游戏天气确定性计算，没有访问外部天气接口或定位。


## v0.4 持续兴趣与消除玩法

`hobbies.js` 提供六种三步计划的数据、权重、材料前提、开工和完成规则；由 life.js 在同一事件时间线上调用。暂停后恢复原活动，重复邀请同一项目不会重复开工。项目状态记录stage/editions/paid，开工时固定context/sourceIds；完成后生成带三个活动ID的手作。因果日志记录步骤，精选记忆只记成品，知识只记首次学会。

`arcade.js` 是连连看与消消乐纯引擎；`arcade-ui.js` 是界面，`tokens.js` 是内置小图标，`arcade.css` 管理手机布局。games.cleanBox统一校验五种非棋类小游戏，life.recordMiniGame检查完成条件后写入关卡册与记忆。小游戏独立随机数入档，解题不会偷偷消耗生活决策随机数。消消乐先结算并保存稳定结果再播放动画。

目前没有玩家账号。程序部署与世界保存是两个独立概念：GitHub只有程序，每个浏览器保存一个世界。未来角色定制不应修改全局模板以覆盖现有角色；应显式创建角色实例并迁移存档。


## v0.5 扩展边界

`arcade-plus.js`在基础arcade前加载，为旧引擎添加移动/难度/特殊棋，旧数据按legacy/classic解释。`board-games.js`围棋/象棋为纯规则，导入时回放合法历史；`board-games-ui.js`承载教学与局内交互。

`country.js`提供物资、农事和钓鱼规则。life.growPlants同时调用田地增长，按天气6小时时段和浇水到期时间分段积分；逐次打开与一次离线结果相同。自主garden记录具体gardenJob（地块/作物/动作），fish记录开工消耗与既定鱼种，结果不在界面重抽。手动钓鱼使用同一背包但独立可暂停的一竿，实时游戏窗口暂停原生活，闭窗恢复。看商店和田地面板不会强制暂停世界。

`companions.js`校验实例外形、图片和受限AI方案，性格写既有preferences；新世界unbound，旧世界original。`expedition-ui.js`负责农事/商店/钓鱼/角色表单与作物可见表现。app只做模块连接，state始终是唯一事实来源。

三个场景使用相同画布尺寸和各自导航多边形，视角与角色实际地点仍分开。无远程服务；上传图片是浏览器本地文件处理。

## v0.6空间与时间

`village.js`是纯规则：区域、障碍、路径、行程插值、居民日程；`village-view.js`使用随包提供的Phaser绘制相机、深度、像素地面、精灵与天气，不能给玩家发奖励或编造记忆。`app.js`连接命令与已有交互面板。旧scenes/navigation仅保留兼容，不再控制当前世界位置。

`life.start`准备材料，然后创建旅途，将activity.startedAt/endsAt顺延到抵达后的开工与完工时刻；途中进度为零。advance在完成边界及最终时刻结算行程；恢复暂停工作从当前地点重新计算路程，不重新取用材料。手动walk有60秒驻足期，再恢复原活动；连续改方向不生成新日记。

NPC属于每份存档，日程基于时间、天气和已经发生的发现事实；关系、借还书、看过的成品写在village.contacts中。UI走近居民后再发邻居命令；命令校验距离和书籍进度，以明确事件写入记忆。

## v0.6.1 表现层

village-view.js在运行时提取身体和双腿，按实际移动距离驱动反相步态；不保存动画相位。village.js固定地理路线使用有界缓存和优先队列，返回独立坐标副本。play-layout.js用ResizeObserver与MutationObserver重排棋盘与工具区；polish-init.js启动它，polish.css最后加载。expedition-ui.js的动画只展示country.js的钓鱼事实，连续收线仍通过原act入口结算。

## v0.7 口袋生活

`pocket-games.js` 提供数织唯一解题库和可重播 2048；`pocket-ui.js` 管理触摸/键盘/撤销。`games.cleanBox` 统一补空/校验，`life.recordMiniGame` 在完成后去重记忆。小游戏不消耗世界随机数。

`hobbies.js` 在三步完成时根据开工 context/sourceIds 与原始梦种生成 letter 快照；`postcards.js` 只呈现、标已读和本机下载图片。`village-view.js` 的笔尖/蒸汽/翻页/呼吸没有写世界状态。

`sw.js` 导入 `offline-worker.js` 与明确 `offline-manifest.js`；`offline.js` 注册、核验、申请存储与先保存后更新。网页仍无后台服务器，原生 iOS/云同步未实现。
