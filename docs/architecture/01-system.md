# 世界系统 v0.2

## 世界先成立，AI再表达

玩家留下梦种 → 保存素材事实 → 规则产生候选方案 → 玩家选择/角色计划 → 检查前提 → 发生事件并更新状态 → 写入经历与知识 → 影响下一次选择。自然语言只是这个过程的可读表达。

`life.js` 是独立于画面的纯 JavaScript 世界引擎。输入为状态和绝对时间；不会访问网络、DOM或浏览器存储。`app.js` 用状态渲染场景、处理邀请；`storage.js` 保存；`gomoku.js` 负责棋局。

## 小脑袋

候选活动有基础倾向，受天气、精力、性格偏好、当前知识和未完成梦种影响。先筛去不满足硬条件的动作，再用保存的随机种子进行带权选择。高分意味着更常发生，不等于每次必选。选择时保存理由和候选分数，不能事后让AI补编动机。

本版实现：读书、喝茶、研究、休息、看天气、制作、陪玩家下棋。钓鱼只作为“没有鱼竿，条件不足”的规则示例，不是假装已有钓鱼玩法。角色动作暂用正背面贴图，活动含义以真实状态为准。

## 时间与连续生活

活动含 startedAt、endsAt、durationMs、progressBase。打开游戏不重抽活动、不重置进度。暂停存入栈，邀请结束后恢复剩余时长与章节。离开期间不需让电脑常开，下次按事件时间逐步结算。种植增长按时间区间计算，并保存生长基准，避免频繁打开比离线打开多长一截。

正常阅读时长数小时。首个梦种研究45秒、制作45秒，植物生长约90秒，雨天约65秒，是明确的Demo加速。没有把真实时间假装成已联网运行的服务器。

## 硬规则和软因果

硬规则：没有知识不能制作相应梦种；植物的雨水/浇水影响水分和成长；已产出的同一物件不能重复发放；没有鱼竿不能选钓鱼。

软因果：她可能因喜欢阅读和下雨选择读书；精力低时更偏向休息；新梦种提高研究倾向。未来AI可以提出符合现有动作与素材库的建议，规则校验后才可生效。

示例因果链：你记录植物梦种 → 她查书 → 得到这颗梦种的照料知识 → 种下植物 → 雨/照料使其成长 → 纸鹤带来旧温室便笺。便笺存在，完整温室地图与NPC尚未实现。

## 三层记忆

1. 素材记忆：`fragments` 保留梦种原文和时间，是故事的来源。
2. 经历记忆：`events` 保存决策、学习、制作、生长等因果事件；`memories` 是精简的可读重要经历，普通走动不入账。
3. 长期记忆：`knowledge` 保存已学会的知识与来源；`preferences` 保存性格倾向。当前尚未实现复杂性格随经历演化。

每层都有稳定ID。产物带 sourceIds，能找回原文和相关经历；新梦种可关联旧物的素材来源。事件历史有Demo容量上限，并非无限数据库或语义向量记忆系统。

## AI边界

现版本为本地组合规则，另有手动 ChatGPT 往返：用户查看并复制材料，自行提交给 ChatGPT，再导入结构化JSON。只接收 name、description、kind、color、thought 等展示提案；梦种来源、知识门槛、时间与奖励由引擎控制。禁止执行模型给的代码，禁止直接插入HTML。

将来自动接口接入应置于独立适配器，沿用同一个校验入口。ChatGPT订阅与API计费分开；当前没有后台AI自动调用或API密钥。
