# 《梦乡》：可行走世界与生活手感提案

日期：2026-09-30。来源：制作人v0.5试玩反馈。用户随后明确“OK 开始吧”，已采纳并实现为v0.6第一片街区；以下保留分析来源。实际规则和本版边界见[08-village-v6.md](08-village-v6.md)，功能与发布状态以STATUS.md为准。

## 用户确认与本轮边界

已确认：游戏名称《梦乡》；走动需要自然；希望有类似星露谷与旧摩尔庄园的地图空间、小比例角色、NPC，以及更好的桌面游戏体验。保留原有画风、自主生活、梦种与碎片参与方向。本轮明确先分析、给建议；没有要求立即重写或发布。

以下地图布局、居民数量、控制方式、技术路线均是开发协作者提案。手机仍是已有目标，本次反馈不等于取消手机支持。

## 现有实现为什么呈现“网页感”

1. `game/style.css`的`.cottage`固定941:1672比例且最大540px，桌面仍然显示手机形状的场景。世界坐标、画面和界面高度绑定。
2. `game/scenes.js`提供三张独立背景、各自的地面区域和热点。`app.js`切换背景图；没有连接各地点的道路与跟随摄影机。
3. `game/navigation.js`已有场景内A*寻路，但路径保留格点折线。人物恒速起停，少量正背面动作加翻转承担方向变化，容易突然转向、滑步。
4. `app.js`在活动地点变化时把人物放到目标场景入口，然后在该场景寻路。决策与活动切换没有完整的途中过程。
5. 大部分互动打开面板，实际地面、道具、角色动作的变化偏少。背景里的树、家具和屋顶无法作为独立前景遮挡人物。
6. 当前EXE是同一网页运行时的桌面启动器；换扩展名不能替代空间、镜头、输入、动画和声音设计。

v0.5验证了日常规则、内容循环和存档等系统；表现层尚未形成可探索的连续空间。此判断不代表现有系统需要全部重做。

## 建议的第一片世界

先设计小而完整的生活街区：小屋室内通过门连接室外，小院沿步道通往路口，路口连接邻居家、杂货铺与河边。室外可连续行走；室内允许经过门的短过渡，无需强求所有区域完全无加载。

世界尺寸大于视口。普通视角看清人物与附近可互动对象；镜头平缓跟随或允许浏览，缩远时才看整个街区。电脑窗口变宽应看到更多空间，不能拉伸人物；手机以同一世界的较小视口显示，不把整幅地图和桌面UI硬缩进手机。

地图中至少有一个绕行障碍、一处前景遮挡、一座桥和清楚的门口。这些实际空间关系用于验证角色是否落在世界里。画风保持现有暖色与角色辨识度，但需独立地面、建筑、树冠、物件和四方向人物素材，不能只拼接现有竖幅插画。

## 自主生活与用户参与

建议保留观察跟随、点击邀请/指定目的地，并试验可选短时方向控制。玩家离开或交还控制后，她继续自己的计划。直接控制的时长与模式切换需要小样试玩，尚未定案；不把本作变成必须持续操作的农事游戏。

行为阶段建议为：决定做什么 → 准备出发 → 前往地点 → 到达并摆好工具 → 做事 → 收尾。路程、目的地与中断后的恢复信息必须属于真实状态。行走不能只是活动已经结算后的装饰动画；播种、钓鱼等结果要由合理的活动阶段触发。

在线与离线使用相同时间线。离线按关键到达和完成时间推进，不模拟每一帧脚步；再次打开时还原她所处的途中/到达/工作阶段。此改动需要版本化迁移和长离线、途中关闭、邀请中断及重复结算验证。

行走先完善脚底锚点、地面阴影、四方向动作、方向稳定、速度与步幅匹配、轻微起停过渡。坐下、看书、提工具和进门要有衔接，随后补不同地面脚步声、水声、雨声与界面音量开关。上传的一张角色立绘不会自动具备这些动作；旧立绘与基础小体型角色的兼容方式需另定，不能承诺任意上传图立刻拥有动作集。

## 居民与互动的提案

先2—3名居民，每人有住处、兴趣、有限日程、当前目标与少量经历记忆。天气、资源与实际经历影响选择，例如雨天从采集改为屋檐下整理药草。姓名和外形留给制作人后续创作，不在此固定。

相遇可以是短招呼、借还一本书、分享收成或邀请同坐。居民应实际走到目的地；关系建立有行为来源，而不是靠持续弹出的随机对白。暂不涉及共享NPC归属、多人服务器或每个NPC持续调用大模型。

已有小游戏与生活空间建立入口：棋桌前坐下后开棋盘，河边坐下后开始钓鱼，靠近植物才能照料，已完成的作品可摆在家里。仍可保留方便的菜单入口，避免用户每玩一次都必须长途步行。

梦种仍是核心：例如一个与桂花有关的片段，经规则认可后形成种植线索，种出一株可见的植物，再触发居民来访或食谱交流。提案必须落入有限物品、位置和事件结构，不宣称可无限生成任意世界资产。

## 技术路线建议（尚未批准迁移）

优先试验Phaser承载地图、镜头、动画、碰撞和输入，沿用JavaScript生活规则、内容数据及可复用小游戏。Phaser主要面向桌面与手机浏览器，现有GitHub Pages入口可保留；桌面封装后续单独验证。官方资料：[框架定位](https://docs.phaser.io/)、[摄影机](https://docs.phaser.io/phaser/concepts/cameras)。

这是基于现有代码与双端需求的工程建议，不是已验证的迁移结论。先以一段路、一个角色与一处互动验证渲染及移动端开销，再确定版本和资源规范。引擎不会自动解决美术一致性、日程因果与交互设计。

Godot可作为以后更偏独立客户端时的候选，但需要评估现有逻辑移植与网页/iPhone导出限制，不能仅因为用户想要成熟EXE手感就重写全项目。官方边界：[Web导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)。

世界状态与表现层保持接口分离；保留原存档键，迁移兼容小罗、其他自建角色、梦种、记忆、收藏和未完成棋局。新名称更新产品显示，不创建另一份空白世界。

## 下一次可玩的最小验证建议

分三步，每步都能单独试玩，具体工期尚未估算：

1. 一间小屋、一段路：四方向走路、跟随镜头、遮挡碰撞与门口衔接，桌面宽屏和手机视口。
2. 路连向院子、河边与商店：真实的前往/到达/工作阶段；将既有农事、钓鱼和棋桌接到场景动作。
3. 少量居民与一条梦种因果链：借书、读书、植物与来访在同一个地方持续发生。

体验验收：不用点场景切换按钮也能从家走到河边；转身、停步与坐下连贯；走过树后会被正确遮挡；会遇见一个正在做自己事情的邻居；能邀请、收起互动、恢复日常；退出回来还在同一条可信的时间线上。手机真机手感另行确认。

实现前还需确定地图草图、镜头和操控小样、基础精灵规格。无需先完成全世界设定，也不建议用继续堆小游戏数量代替这些体验验证。
