# 《那边的小日子》：创作方向与世界原则

> 暂定名，可继续修改。用户是制作人，负责创作方向；开发协作者把想法整理为可验证的设计和实现。本文件记录持续有效的设计约定，不替代当前版本状态与验证记录。

## 阅读方式

- 首次理解项目时阅读本页。后续工作先看项目入口、当前任务与最近改动，只读与本次任务相关的设计小节。
- 新想法先进入 [想法收件箱](02-ideas-inbox.md)，讨论后把明确结论更新到对应设计文档，保留来源和决定原因。
- 不要求每轮工作重新阅读全部对话。事实以整理后的文档和真实代码为依据，疑问明确标为待确认，不凭空补成用户已同意的决定。
- 本页的“目标”“未来”是设计意图。已完成的功能以当前版本说明及测试结果为准。

## 我们要创造的体验

地球上的用户与魔法世界中的生灵建立长期联系。用户可以把角色当作另一个世界里的自己，也可以把她当作有独立主意的精神伙伴。她有日常、兴趣、记忆与计划；用户忙时她继续生活，有空时可以加入，也可以邀请她换一件事做。

核心句：**让独自生活和一起玩，成为同一段生活的两种状态。**

体验必须支持十几秒看一眼、两三分钟参与以及一小段较完整的探索。离开不会造成惩罚、关系衰退或重要情节失效。成长表现为生活变丰富，而不是清理越来越长的日常清单。

用户的真实生活碎片是世界生长的材料。吃过的东西、随手记录、心情和梦境，可以经过转化成为物品、灵感或事件的来由，并与过去发生过的事产生联系。用户不需要负责每天写剧情。

## 角色和视觉约定

- 原始角色依据用户自己的魔女手绘；图中名字“小罗”仅为暂用名。
- 保留弯曲的大帽子、月亮与星星、圆眼镜、齐刘海与双麻花辫、红斗篷等辨识特征。
- 圣诞糖果、雪花等属于冬日服装，不把角色的身份限制为全年圣诞主题。
- 游戏内维持已获用户认可的温暖像素童话风格；手绘头像与插画可以保留原画的颗粒感和表情。
- 手机是主要体验目标；不以常驻桌面为前提。电脑双击进入游戏是用户明确希望具备的入口。
- 视觉图可以表达愿景，但不能把一张概念图等同于已经能操作的游戏场景。

## “她有生活”的最低要求

一个活动必须有对象、开始时间、持续时间、状态和原因。不能用每隔几秒换一句台词制造繁忙。

以阅读为例，游戏应能回答：

- 她读的是哪一本书，这本书从哪里来？
- 她为什么现在想读，是正在研究植物、外面下雨，还是精力较低？
- 她读到了哪里，已读多久，准备继续到什么时候？
- 用户离开三小时再回来时，她是还在读、已经读完，还是因为别的事情暂停？
- 这次阅读带来了什么真正的变化，例如学到一种植物的照料方法？

用户可以加入她当前的生活，也可以说“先放下书，我们下一盘棋吧”。活动要能暂停和恢复，或者明确取消；不能为了表现自主就拒绝一切互动。五子棋等小游戏与日常状态衔接，结束后她能回到合适的活动。

手记以值得记住的经历为单位，合并重复行为。当前状态负责说明“她现在做什么”，手记负责说明“发生过什么值得留下的事”，避免重复刷屏。

## 三个层次各自负责什么

| 层次 | 责任 | 不应越权的部分 |
| --- | --- | --- |
| 制作人和设计 | 定义世界的气质、边界、玩法、角色与美术方向 | 不必事先写完每一次小事 |
| 游戏引擎 | 保存世界状态，推进时间，选择活动，执行规则，记录因果与真实结果 | 不把未经验证的文字当作已经发生的事实 |
| AI（接入后的目标） | 理解自由输入的梦境和生活碎片，在允许的范围内提出变化，自然表达已经成立的事实 | 不直接任意改存档，不凭空赋予不存在的道具、地点或能力 |

当前没有接入云端 AI 的玩法必须如实说明使用本地规则，不能称为已经理解任意输入。AI 是未来可以替换的表达和提议层，游戏基础生活不应依赖每分钟请求模型。

## 有规则的世界，也有不完全一样的选择

### 硬因果：满足条件才发生

硬规则负责物理与玩法的一致性。例如：

- 下雨可以为露天、能接到雨的植物补水；室内植物不能仅因为天气变化就自动被浇透。
- 有鱼竿并能到达相应钓点，钓鱼才可能成为活动候选。
- 拥有种子、合适位置并满足种植条件，才会出现真实植物。
- 学到知识、消耗材料、得到物品都需要在状态中实际记录；一句对话不能替代这一步。

这些例子是目标规则，不意味着当前版本已经有天气、植物或钓鱼系统。

### 软因果：共同影响选择的倾向

在满足硬条件的活动之间，根据基础兴趣、天气、精力、性格、近期经历以及少量可复现的随机性计算偏好。偏好影响被选择的概率，不永远只选分数最高的一件事。

每次重要选择保存决定时的相关状态与主要原因。随机种子或已经作出的选择需要保留，刷新游戏不能把既定经历反复改写。软因果的解释只能使用真实参与决定的因素。

### 一条能够被追溯的成长链

目标示例：

> 她借到一本植物书 → 下雨且精力较低，使阅读更有吸引力 → 阅读后认识一种植物 → 获得条件后种下它 → 植物产生特定影响，吸引一个相关 NPC 来访。

链条中的每一步有自身条件，可能隔几天发生，也可能暂时停在某一步。系统不能直接跳到“陌生人来了”，然后补写一段并未发生的前因。借书、完整植物系统和 NPC 来访目前属于后续设计示例。

## 记忆的三个层次

| 层次 | 保存什么 | 后续怎样使用 |
| --- | --- | --- |
| 材料记忆：梦种等 | 用户输入的片段、提取出的元素、来源、可用状态、衍生物关联 | 作为创造材料，与当前生活和旧材料组合 |
| 经历记忆 | 某次阅读、共同下棋、一次制作、谁参与、何时发生、真实结果、原因链接 | 回看经历，解释变化，作为后续事件的前提 |
| 长期知识与偏好 | 学会的知识、逐渐形成的习惯、稳定关系与喜好，并注明来源 | 改变未来活动候选与选择倾向，支持持续成长 |

梦种是当前讨论中的称呼，可按后续创作方向调整。三层之间通过标识和来源链接关联，不能让一份无限增长的聊天文本代替结构化存档。

重要经历应该能点开看见来源。一个物件如果来自用户的一次梦，就保留“原始片段 → 转化或制作 → 物件 → 后续影响”的关系。只有发生过的事情才能进入事实记忆；想象中的愿望与待执行计划单独保存。

原始日常默认属于个人资料。未来分享衍生植物或作品时，不默认把原始日记一起公开。

## 时间和离线生活

关闭游戏不要求设备一直运行。退出时保留活动、计划、时间与必要条件；重新进入时按规则推进到当前时间，并解释期间的结果。要避免每次打开都重新抽一套经历。

离线日常可以自行完成；关系里重要的共同决定可以保留，等用户参与。长时间未打开不造成生病、死亡、财物损失或关系惩罚。具体离线跨度、合并记录策略和可生成事件上限由实现阶段明确，避免一个月没打开就堆积上千条手记。

## 世界为什么能继续长大

房子完成后成为生活发生的地方。阅读、研究、朋友、收藏和现实片段会给它带来新用途。搬家可以是角色的愿望，不是强制重置进度的方式。

持续新鲜感来自旧事物和新输入的组合、有后果的选择以及不断延伸的关系。每一个小目标可以圆满完成。有限的素材和明确的规则也能承载多样的经历；不能把“可以继续生长”承诺成无限地图、无限原创美术或永远不会重复。

## 实现与愿景的边界

- **已被试玩确认的基础：** 像素风小屋原型和角色自主走动，用户认可整体感觉，并提出略微加快走动速度。
- **本轮已完成的独立组件：** 本地五子棋棋盘、黑白轮换、基础对手、存档恢复、悔棋与明确重新开局；是否在当前主界面完成集成，以版本状态和整体验证为准。
- **本轮开发方向：** 更持久和可解释的活动、生活碎片融入、减少重复手记、D 盘项目与便捷启动、可迁移存档。完成程度由当前版本文档维护。
- **后续愿景：** 云端 AI、自动跨设备同步、真实多人生灵关系、完整 NPC 社交、钓鱼、扩展探索地点及更复杂的因果链。未接入前不得作为现有能力展示。

## 评估每次迭代的问题

1. 用户回来时，能否看懂她正在做什么，以及为什么？
2. 用户加入、打断、离开后，状态和记忆是否连续？
3. 用户留下的碎片有没有真实改变世界，而不仅是一段新文案？
4. 后来的变化能否追溯到真实发生的旧事？
5. 新功能让生活更有意思了吗，还是增加了打卡与维护负担？
6. 美术、台词和系统对当前能力的表达是否一致？
